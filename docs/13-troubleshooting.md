# عیب‌یابی

## ۱. سرور بالا نمی‌آید

### `EADDRINUSE: address already in use :3000`

پورت ۳۰۰۰ اشغال است.

```bash
# ویندوز
netstat -ano | findstr :3000
taskkill /PID <PID> /F

# لینوکس / مک
lsof -ti:3000 | xargs kill -9
```

یا `PORT` را در `server.ts` تغییر دهید.

### `Cannot find module 'tsx'` یا `vite`

```bash
rm -rf node_modules package-lock.json
npm install
```

### `ERR_MODULE_NOT_FOUND` هنگام اجرای `npm run dev`

مطمئن شوید از ریشه پروژه اجرا می‌کنید (جایی که `server.ts` قرار دارد).

## ۲. ورود ناموفق است

### همیشه `401 نامعتبر`

| علت | بررسی |
|-----|-------|
| نام کاربری `admin` | عمداً مسدود است؛ از `heliya` استفاده کنید |
| رمز اشتباه | رمز ادمین: `heliya84` |
| کاربر در JSON نیست | `data/system_users.json` را بررسی کنید |
| ارقام فارسی در رمز | کد به‌طور خودکار تبدیل می‌کند، اما بهتر است لاتین وارد کنید |
| حروف بزرگ/کوچک نام کاربری | تطبیق بدون حساسیت است، اما فاصله اضافی را حذف کنید |

### `403 عدم دسترسی صادرکننده`

کاربر توسط ادمین مسدود شده است (`isActive: false`). از پنل ادمین → لیست کاربران → «آزادسازی دسترسی».

### نشست قبلی پاک می‌شود

اگر در `localStorage` نقش `ADMIN` با نام کاربری غیر از `heliya` باشد، اپ عمداً آن را پاک می‌کند. دوباره وارد شوید.

### خروج خودکار بعد از رفرش

`localStorage` توسط حالت ناشناس یا سیاست مرورگر پاک می‌شود. بررسی کنید که `sipaad_issuer_user` و `helibar_auth_token` باقی می‌مانند.

## ۳. صفحه با پیام اشتراک منقضی قفل شده

```
403 SUBSCRIPTION_EXPIRED
```

راه‌حل‌ها:

1. **ورود ادمین** → `/api/admin/users/{id}/approve-payment`
2. **تنظیم دمو** (فقط توسعه):

```bash
curl -X POST http://localhost:3000/api/subscription/set-demo \
  -H "Content-Type: application/json" \
  -d '{"days": 30}'
```

3. **بازنشانی دستی** در `data/system_users.json`: مقدار `createdAt` را به امروز تغییر دهید و سرور را ری‌استارت کنید.

> بنر زرد = کمتر از ۱۴ روز. بنر قرمز چشمک‌زن = کمتر از ۷ روز. این‌ها فقط هشدار هستند، نه خطا.

## ۴. اتصال به سپاد برقرار نمی‌شود

### `test-connection` نتیجه `success: false` می‌دهد

مرحله به مرحله:

```bash
# ۱. بررسی DNS و دسترسی
curl -I https://services2.sipaad.ir/ITMFreighter.asmx

# ۲. بررسی خروجی اینترنت سرور
curl https://api.ipify.org

# ۳. تست هش
curl -X POST http://localhost:3000/api/sipaad/hash \
  -H "Content-Type: application/json" \
  -d '{"companyCode":"24981","password":"test"}'
```

| نشانه | علت | راه‌حل |
|-------|-----|--------|
| `serverIp: نامشخص` | سرور به اینترنت بین‌الملل دسترسی ندارد | پروکسی، DNS یا فایروال |
| `freighterStatus: FAIL` با IP موجود | IP در whitelist سپاد نیست | درخواست افزودن IP به پشتیبانی سپاد |
| تایم‌اوت بعد از ۶ ثانیه | فایروال پورت ۴۴۳ را می‌بندد | باز کردن خروجی HTTPS |
| `445001` در ثبت بارنامه | salt یا رمز نامعتبر | `SIPAAD_COMPANY_PASSWORD` را بررسی کنید |
| `445030` | فیلد اجباری ناقص | `BOL` را کامل کنید |

### هش با خروجی مورد انتظار فرق دارد

- طول خروجی باید **۱۲۸ کاراکتر** باشد.
- ترتیب اتصال: `companyCode` + `passwordSha512` + `salt` (بدون جداکننده).
- `salt` باید عدد صحیح باشد، نه رشته با فاصله.
- رمز باید بدون فاصله اضافی ابتدا/انتها باشد.

### خطای SSL / گواهی

در محیط توسعه می‌توانید موقتاً `NODE_TLS_REJECT_UNAUTHORIZED=0` بگذارید، اما **هرگز در تولید**.

## ۵. کد دوعاملی دریافت نمی‌شود

### `pending` خالی می‌ماند

```
۱. POST /api/otp/trigger با driverId صحیح
۲. بررسی otpRequestsStore: آیا رکورد PENDING ساخته شد؟
۳. بررسی شماره موبایل راننده در plates.json یا system_users.json
۴. بررسی رسیدن پیامک به پنل SMS
```

### Webhook خطای `INVALID_WEBHOOK_PAYLOAD`

فرمت مورد انتظار:

```
DRIVER:09123333333-SMS:کد تایید شما 48213 می باشد
```

بررسی‌ها:
- شماره باید با `09` شروع شود و ۱۱ رقم باشد.
- کد باید ۴ تا ۶ رقم باشد.
- اگر پنل پیامک شما JSON می‌فرستد، ساختار `{ "driver_phone": "...", "message": "..." }` را استفاده کنید.

### کد اشتباه به راننده دیگری تخصیص می‌یابد

تطبیق بر پایه **۱۰ رقم آخر** شماره انجام می‌شود. اگر دو شماره در ۱۰ رقم آخر یکسان باشند (مثلاً `+98912...` و `0912...`)، تطبیق اشتباه می‌شود. شماره‌ها را یکسان‌سازی کنید.

### کد منقضی شده

انقضای پیش‌فرض ۲ دقیقه است. دوباره `POST /api/otp/trigger` بزنید.

## ۶. ظرفیت پلاک تکمیل شده

```json
{
  "detail": "تکمیل ظرفیت پلاک",
  "message": "سقف مجاز ثبت پلاک (150) برای حساب شما به اتمام رسیده است."
}
```

راه‌حل‌ها:

1. ادمین → `PATCH /api/admin/users/{id}/capacity` با مقدار مجاز (`50`, `150`, `350`, `550`, `700`)
2. غیرفعال کردن پلاک‌های بلااستفاده (شمارش فقط `is_active = true`)
3. بررسی رکوردهای تکراری — dedup بر پایه پلاک **یا** کد ملی راننده است

## ۷. آپلود اکسل شکست می‌خورد

| خطا | علت | راه‌حل |
|-----|-----|--------|
| `LIMIT_FILE_SIZE` | فایل بیش از ۲۵MB | فایل را تقسیم کنید |
| `Unexpected field` | نام فیلد اشتباه | فیلد باید `file` باشد |
| ستون‌ها شناسایی نمی‌شوند | سربرگ اشتباه | از قالب `/api/drivers/excel-template` استفاده کنید |
| ارقام فارسی در وزن | پارس ناموفق | ستون وزن را عددی لاتین کنید |

نمونه درخواست صحیح:

```bash
curl -X POST http://localhost:3000/api/drivers/bulk-upload \
  -H "Authorization: Bearer <TOKEN>" \
  -F "file=@drivers.xlsx"
```

## ۸. پردازش دسته‌ای خطا می‌دهد

### برخی آیتم‌ها همیشه `ERROR` هستند

در پیاده‌سازی فعلی **هر آیتم پانزدهم عمداً** خطا می‌گیرد:

```ts
const isError = (itemIndex + 1) % 15 === 0;
```

این رفتار شبیه‌سازی برای تست است. برای حذف، این بلوک را در `POST /api/batch` بردارید.

### همه آیتم‌ها گیر می‌کنند

`workerConcurrency` را کاهش دهید (مثلاً ۴) تا محدودیت نرخ سپاد رعایت شود.

### بارنامه تکراری ساخته می‌شود

`idempotencyKey` هر job باید یکتا باشد. اگر کلید را از پلاک و تاریخ می‌سازید، دنباله (sequence) را اضافه کنید.

## ۹. سهمیه سوخت صفر یا اشتباه است

| نشانه | علت |
|-------|-----|
| همیشه صفر | پلاک در `waybillsStore` با پلاک بارنامه تطبیق نمی‌یابد |
| عدد تصادفی هر رفرش | کد fallback هش پلاک را نادیده می‌گیرد (نباید رخ دهد) |
| تاریخ دوره اشتباه | Express تاریخ‌های ۱۴۰۵ را ثابت دارد؛ از `backend/jalali_periods.py` استفاده کنید |
| یک روز جابه‌جایی | منطقه زمانی سرور با `Date.UTC` هم‌تراز نیست |

### بررسی تطبیق پلاک

```bash
curl "http://localhost:3000/api/fuel-inquiry/43ع78977?stage=1"
```

اگر `waybill_count` صفر است ولی بارنامه دارید، قالب `plate_number` در `waybills.json` و `plates.json` باید یکسان باشد (با/بدون فاصله و خط تیره).

## ۱۰. خطاهای بیلد و تایپ

### `tsc --noEmit` خطا می‌دهد

```bash
npm run lint
```

خطاهای رایج:
- `Property 'x' does not exist on type 'Y'` → فیلد را در `src/types.ts` اضافه کنید
- `Type 'string' is not assignable to type 'LicensePlateLetter'` → حرف پلاک باید از union مجاز باشد

### بیلد تولید شکست می‌خورد

```bash
npm run build
```

اگر `esbuild` خطا داد، مطمئن شوید `--packages=external` در اسکریپت هست (وابستگی‌های Node نباید bundle شوند).

### صفحه سفید بعد از بیلد

- کنسول مرورگر را باز کنید؛ اغلب خطای `Failed to load module` است.
- بررسی کنید `dist/index.html` به فایل‌های hash شده اشاره می‌کند.
- `base` در `vite.config.ts` نباید مقدار اشتباه داشته باشد.

## ۱۱. CORS و درخواست‌های cross-origin

| نشانه | راه‌حل |
|-------|--------|
| `blocked by CORS policy` | از همان پورت ۳۰۰۰ استفاده کنید |
| `allow_credentials` با `*` | در FastAPI origin دقیق تنظیم کنید |
| هدرهای اشتراک در دسترس نیستند | `Access-Control-Expose-Headers` باید شامل `X-Sub-Warning` باشد |

## ۱۲. داده‌ها از دست رفته‌اند

### بعد از ری‌استارت، پلاک‌ها برنگشتند

`plates.json` را بررسی کنید:

```bash
cat data/plates.json | head -30
```

اگر فایل خالی یا `[]` است، داده‌ای ذخیره نشده. بررسی کنید که `savePlatesToDisk()` بعد از تغییر صدا زده شود.

### فایل JSON خراب شده

```bash
# اعتبارسنجی
node -e "JSON.parse(require('fs').readFileSync('data/plates.json','utf8'))"
```

اگر خطا داد، از پشتیبان بازگردانید:

```bash
cp data-backup-20261102/plates.json data/plates.json
```

### OTPها و تخصیص‌ها گم می‌شوند

این‌ها در حافظه‌اند و persist نمی‌شوند. برای پایداری، به Redis یا جدول دیتابیس منتقل کنید.

## ۱۳. مشکل تم و نمایش

### متن در تم روشن خوانا نیست

`index.css` برای هر تم override دارد. اگر کلاس جدیدی اضافه کرده‌اید که رنگ ثابت دارد، در `[data-theme="light"]` و `[data-theme="sepia"]` هم بازنویسی کنید.

### اعداد فارسی نمایش داده نمی‌شوند

از `toPersianDigits` در `src/lib/iranPlate.ts` استفاده کنید، نه تبدیل دستی.

### چیدمان RTL به‌هم می‌ریزد

از ویژگی‌های منطقی Tailwind (`ms-*`, `me-*`, `ps-*`, `pe-*`) به‌جای `ml-*`, `mr-*` استفاده کنید.
